# MCHeli Vehicle Configuration Reference

This reference was generated by auditing the actual parser/load code in:

- `MCH_BaseVehicleInfo.loadItemData` for shared vehicle keys.
- `MCP_PlaneInfo.loadItemData` and `MCP_EntityPlane` for fixed-wing keys and formulas.
- `MCH_HeliInfo.loadItemData` and `MCH_EntityHeli` for helicopter keys and rotorcraft formulas.
- `MCH_TankInfo.loadItemData` for tank keys.
- `MCH_TurretInfo.loadItemData` for turret/static-weapon keys.
- `MCH_ShipInfo.loadItemData` for the existing ship/boat category.

Parser matching is case-insensitive for most newer keys, but several legacy keys are compared after the loader lower-cases the item name. Pack makers should keep the spellings shown here for readability and compatibility. Values are optional unless marked **required**. If omitted, the constructor default shown below is used; data validation then adds missing HUDs/camera positions and requires at least one seat and at least one texture.

## Value formats

| Format | Meaning |
|---|---|
| `boolean` | `true` enables; `false` disables. Invalid text falls back to the parser default for that key. |
| `int[min..max]` / `float[min..max]` | Numeric value clamped by `toInt`/`toFloat` to the shown parser limits. |
| `vec3` | Three comma-separated floats: `x, y, z`. |
| `rot` | Three comma-separated floats: `rotX, rotY, rotZ` in degrees. |
| `part pose` | `x, y, z, rotX, rotY, rotZ` unless the key notes a different order. |
| `recipe` | Legacy MCHeli recipe row/material syntax consumed by the base info manager. |
| `list` | A comma-separated list whose positional fields are described in the per-type docs. |

## Required minimum config

Every vehicle config needs enough data to pass `isValidData`:

1. At least one seat (`AddSeat`, `AddGunnerSeat`, `AddFixRotSeat`, or an auto-created UAV seat when `UAV`, `NewUAV`, or `TargetDrone` is true).
2. At least one texture. The constructor adds the file name as the first texture, so this is normally satisfied unless reload logic clears textures.
3. A usable item/model supplied by the content loader outside the text keys.

Most old packs safely omit new flight-model keys; the defaults preserve legacy-feeling behavior and the parser treats `Mass` as an alias of `InertiaMultiplier`.
